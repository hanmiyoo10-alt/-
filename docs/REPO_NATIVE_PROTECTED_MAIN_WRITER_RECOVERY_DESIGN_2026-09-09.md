## 5. Required behavior

Protected exact-candidate mode gains a native-enforcement observation step using read-only repository branch metadata.

Conceptual sequence:

```text
replay bounded payload on exact main base
→ exact candidate C
→ push C to unique staging ref S
→ run Required on exact C
→ Required PASS
→ re-read main identity
→ re-read main native protection state

if native Required enforcement is OFF:
  preserve existing fast-forward-only direct landing behavior

if native Required enforcement is ON:
  DO NOT direct-push main
  preserve exact gated staging ref S as recovery transport
  emit bounded PR-recovery coordinates
  return fail-closed recovery-required result
```

Required bounded output vocabulary:

```text
MAIN_WRITE_NATIVE_PROTECTION_ACTIVE
MAIN_WRITE_CHECKED_PR_REQUIRED
  base=<exact main base>
  commit=<exact gated candidate>
  ref=<exact preserved staging ref>
```

The helper must not claim `MAIN_WRITE_LANDED` in this state.

## 6. Recovery transport contract

A preserved recovery ref is not main authority and does not become production authority.

It exists only so an authorized operator or connected repository actor can open a normal PR containing the exact machine-generated payload.

Recovery PR requirements:

```text
base = main
head = preserved exact gated ref
changed paths remain within original allowlist
normal PR SimCore CI / Required = PASS
merge only through ordinary protected-branch PR semantics
post-merge main re-read required
```

For release receipts, the receipt/spec-shadow contents must be the exact machine-generated bytes from the failed transaction. They must not be manually reconstructed from memory.

## 7. Cleanup semantics

A recovery-required staging ref must not be deleted before the PR is created.

After successful checked PR merge and durable main reobservation, that recovery ref may be deleted as cleanup.

If the PR is abandoned or superseded, cleanup is a separate bounded action after evidence is preserved.

Ordinary gate failure continues to clean its staging ref. `--verify-gate-only` continues to clean its staging ref.

## 8. Failure and safety rules

Forbidden:

```text
force push
force-with-lease
broad bypass actor
PAT/deploy-key addition as emergency repair
manual receipt invention
reuse of a Required result for a different commit
silent downgrade from protected mode to legacy direct mode
claiming automatic main landing when a PR is still required
```

Main moving after the gate remains a replay/re-gate condition and takes precedence over PR recovery coordinates.
