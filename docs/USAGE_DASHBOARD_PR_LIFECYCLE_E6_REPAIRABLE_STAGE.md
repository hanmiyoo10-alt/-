## Goal

Reduce release coordination state without weakening release validation.

The normal command remains one command:

```text
/usage-dashboard stage <release/usage-dashboard-source-branch>
```

The source branch and generated candidate now have different authority.

## Authority split

### Source branch

`release/usage-dashboard-*`

Assistant-authored source of intent only. Generated release output is rejected by the existing stage policy.

### Derived candidate branch

`stage/usage-dashboard-<product-version>`

Controller-owned materialized output only. The assistant does not hand-edit it.

Every stage transaction freezes:

- trusted main base SHA;
- exact source branch SHA;
- source-intent merge-base;
- derived candidate expected parent SHA.

The read-only materialization job reconstructs the target tree from trusted main plus the exact source-intent patch, then runs the release materializer, generic two-pass reconciliation and focused behavior smoke.

## Reentrant repair

A second `/stage` after CI discovers a defect does not reuse previous generated bytes as source authority.

It reconstructs a fresh tree from the newly frozen source SHA, then writes a new commit whose parent is the previous controller-owned candidate head.

Therefore:

- candidate history remains fast-forward-only;
- no force push is used;
- old generated output is never source authority;
- the same derived branch and same release PR can advance after a source fix;
- ordinary `-v2/-v3` replacement candidate branches are no longer required.

## Privilege boundary

The E4-B/E5 security boundary remains intact.

### Read-only materialization

- checks out immutable trusted main;
- receives no repository write credential;
- applies frozen source intent;
- executes candidate materializer/build/test code;
- builds an immutable Git bundle.

### Write-only derived candidate writer

- receives `contents: write`;
- checks out only trusted control-plane code;
- never runs materializer, behavior tests or source stage policy from candidate code;
- verifies bundle digest, tree/path/mode policy, exact expected parent and remote CAS;
- performs a plain fast-forward push;
- post-verifies the remote SHA.

### PR management

A separate trusted job owns PR/action permissions. It never executes candidate code.
It creates or reuses exactly one open PR for the deterministic derived candidate branch and explicitly dispatches full candidate validation on the exact derived head.

## Receipts

The control plane records:

- `UD_STAGE_ACCEPTED` with source/candidate identity;
- `UD_CANDIDATE_READY` with exact candidate SHA, PR and smoke status;
- `UD_STAGE_REJECTED` with failure class and safe next action.

The safe repair action is intentionally the same command again.
