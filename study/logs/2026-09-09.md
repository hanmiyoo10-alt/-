## 정처기 문제 분류 기준

이 교재는 필기 기출문제집이므로 실제 실기 섹션은 없지만, 문제를 공부 목적상 `필기 이론형`과 `실기 직접 연계형`으로 나눠 관리하기로 함.

### 필기 이론형
- 하: 용어 정의, 기본 개념, 단순 암기형
- 중: 유사 개념 비교, 절차/관계/원리 판별형
- 상: 여러 개념을 결합한 판단, 계산/설계가 섞인 응용형
- 중심 영역: 소프트웨어 설계, 정보시스템 구축관리, 소프트웨어 개발의 테스트/형상관리/개발방법론, 데이터베이스 이론 일부

### 실기 직접 연계형
- 하: 기본 SQL, 기본 문법/연산자, 단순 코드 한두 줄 추적
- 중: SELECT 조건/정렬/집합연산, 반복문·배열·함수·객체 흐름 추적, 정규화/키/관계대수 적용
- 상: 중첩 SQL, 복합 코드 실행 추적, 포인터·상속·오버라이딩 등 상태 변화가 많은 코드, 서브넷/페이지 교체/알고리즘 계산형
- 중심 영역: 프로그래밍 언어 활용, 데이터베이스 구축, 소프트웨어 개발의 알고리즘/테스트, 일부 네트워크·보안 계산 문제

### 실기 연결 우선도
1. 프로그래밍 언어 활용
2. 데이터베이스 구축
3. 소프트웨어 개발
4. 정보시스템 구축관리
5. 소프트웨어 설계

다음 단계부터 문제를 풀 때 `이론/실기연계 + 하/중/상 + 과목 + 오답원인` 태그를 붙여 `study/problems/`에 기록한다.

## 현재 목표선

- 이론형/실기연계형을 구분하지 않고 **난이도 하·중 문제는 전부 맞히는 것**을 1차 목표로 설정.
- 난이도 상 문제는 현재 필수 정복 대상이 아님.
- 상 난이도 문제는 중 난이도까지의 개념이 실제로 안정적으로 연결되는지 확인하는 진단용 문제로 활용.
- 복습 우선순위는 `중 난이도 오답 > 하 난이도 오답 > 상 난이도 오답`으로 둔다.
- 하 난이도 오답은 지식 공백 또는 암기 누수로 간주하고 즉시 보완한다.
- 중 난이도 오답은 핵심 학습 대상으로 분류하여 원인과 판별 기준을 반드시 기록한다.

## 하 난이도 분류 v1

판정 기준: `한 개념을 알고 있으면 바로 답하거나, 한 단계 적용으로 끝나는 문제`를 하 난이도로 본다. 교재 자체의 A/B/C 등급과는 별도 기준이다.

### 1과목 소프트웨어 설계
- 객체지향 기본 용어: 클래스, 캡슐화, 상속, 다형성, 추상화
- 응집도/결합도의 정의 수준 문제
- 애자일 기본 가치와 특징
- 폭포수/프로토타입 등 생명주기 모형의 대표 특징
- UML 다이어그램의 대표 용도 구분
- DFD 기본 구성요소/작성 원칙의 단순 회상형
- 디자인 패턴의 정의 및 대표 패턴군 이름 회상형

### 2과목 소프트웨어 개발
- 테스트 종류의 정의: 단위/통합/시스템/인수 테스트
- 하향식 통합의 Stub, 상향식 통합의 Driver
- 블랙박스/화이트박스 테스트 기본 정의
- 경계값 분석 등 대표 테스트 기법의 정의
- 형상관리 도구의 대표 예시
- 소프트웨어 재사용의 기본 장단점
- Divide and Conquer, Greedy, Backtracking 등 알고리즘 기법 이름 구분

### 3과목 데이터베이스 구축
- DDL/DML/DCL 명령어 분류
- 기본키/외래키/후보키 등 키 정의
- 튜플/속성/차수/카디널리티 기본 정의
- 트랜잭션 ACID 기본 특성
- 무결성의 기본 정의
- SELECT/FROM/WHERE/ORDER BY의 단순 기능
- NULL 판정의 `IS NULL` / `IS NOT NULL`
- 단순 SQL 결과 확인 문제

### 4과목 프로그래밍 언어 활용
- C/Java/Python 기본 문법 용어와 예약어
- 변수명 사용 가능 여부
- 기본 자료형/연산자 의미
- C 표준 라이브러리의 대표 기능
- `strlen`, `strcpy`, `strcmp` 등 문자열 함수 의미
- 대입/산술/관계/논리 연산만 있는 짧은 코드 추적
- 입력값을 단순 분리·출력하는 짧은 Python 코드
- 대표 네트워크 포트처럼 단순 암기로 끝나는 항목

### 5과목 정보시스템 구축관리

- 지식/소유/생체 등 인증 유형
- 대표 보안 용어의 정의
- TCP/UDP/HTTP/SSH 등 프로토콜의 대표 특징과 기본 포트
- OS/기억장치/파일 관련 기본 용어
- 클라우드, 디지털 트윈 등 신기술의 대표 정의

### 하 난이도 운영 원칙
- 하 문제는 고민 시간이 길어지면 이미 목표 상태가 아님.
- 틀리면 `암기 누수` 또는 `기본 개념 공백`으로 즉시 기록.
- 같은 개념의 하 문제를 재출제했을 때 설명 없이 바로 정답을 고를 수 있어야 통과.
- 하 난이도 학습 완료 후 중 난이도로 확장한다.

## 실제 이론 공부 방식 관찰

- 사용자가 1회차 1과목 이론을 손필기한 사진 3장을 공유함.
- 문제를 처음부터 교과서식으로 요약하지 않고, **문제 하나를 씨앗으로 정답 핵심 → 보기/유사개념/연관개념으로 가지치기**하는 방식으로 공부함.
- 확실히 모르는 항목은 즉시 채우지 않고 `?`로 표시하여 나중에 회상·보충할 구멍으로 남김.
- 예시 흐름: `Cohesion → Coupling/Structure/Unity?`, `상태 다이어그램 → event → state/message/transition?`, `NUI → Tap/Drag/Press/Flick/Pinch?`, `Transcription Error → Omission/Sequence/Addition?`.
- 긴 정의 문장을 베끼기보다 본인 표현, 영문 키워드, 화살표, 묶음 표시를 이용하여 개념 관계와 차이를 기록함.
- 앞으로 이론 설명은 `정답 핵심 → 헷갈리는 이웃 개념 → 판별 신호 1줄 → 짧은 재질문` 구조를 우선 적용한다.
- 하 난이도에서는 한 문제당 연관 개념을 과도하게 확장하지 않고, 실제 선지 판별에 필요한 가장 가까운 혼동개념 1~3개를 우선한다.
